# Банковские парсеры PDF → CSV для Firefly III

Парсеры выписок российских банков (PDF → CSV) для импорта в [Firefly III](https://www.firefly-iii.org/).

**Статья с полным разбором:** https://standlast.dev/posts/firefly-iii-ru-bank-issue/

## Поддерживаемые банки

Парсеры написаны под выписки формата **ноября 2026** для трёх крупных российских банков:
- **Зелёный банк** (зелёный логотип)
- **Синий банк** (синий логотип)
- **Красный банк** (красный логотип)

⚠️ **Банки меняют вёрстку PDF без предупреждения.** Парсер, работавший в сентябре, может сломаться на октябрьской выписке. Это не баг — это природа PDF. Форкай и адаптируй под свою дату. PR приветствуются.

## Использование

### Зелёный банк

```bash
python parsers/green_bank_parser.py "Выписка по счёту дебетовой карты.pdf" \
  -o green_bank.csv \
  -a "Зелёный-Карта"
```

**Особенности:**
- Расходы пишутся **без знака минус** (доход с `+`, расход без знака)
- Парсер автоматически инвертирует знак для расходов
- Пример строки: `05.11.2026 14:30 Супермаркеты 600,00 15 400,00`

### Синий банк

```bash
python parsers/blue_bank_parser.py "Выписка по счету.pdf" \
  -o blue_bank.csv \
  -a "Синий-Карта"
```

**Особенности:**
- Транзакция размазана на **3 строки**:
  1. Дата операции (одна строка)
  2. Дата обработки + сумма в валюте операции + сумма в валюте карты + комиссия + описание
  3. Время
- Парсер берёт сумму **в валюте карты** (не операции)
- Пример:
  ```
  15.11.2026
  15.11.2026 -83.0 USD -7500.0 0.0 RUB Оплата товаров
  14:30
  ```

### Красный банк

```bash
python parsers/red_bank_parser.py red-statement.pdf \
  -o red_bank.csv \
  -a "Красный-Счет"
```

**Особенности:**
- Тысячные разделители пробелами: `-6 010,00 RUR`
- Хвост `RUR` в конце суммы
- Описание может переноситься на следующие строки
- Парсер использует ленивый regex и склейку строк-продолжений

## Формат CSV

Все парсеры выдают CSV в формате, совместимом с Firefly III импортером:

```csv
date,amount,description,source_name
2026-11-15,-600.00,Супермаркеты - Пятёрочка,Зелёный-Карта
2026-11-15,-7500.00,Оплата товаров,Синий-Карта
2026-11-15,-6010.00,Перевод на карту,Красный-Счет
```

| Поле | Описание |
|------|----------|
| `date` | `YYYY-MM-DD` |
| `amount` | Сумма (отрицательная для расходов, положительная для доходов) |
| `description` | Описание транзакции (категория + детали для зелёного, просто описание для остальных) |
| `source_name` | Название счёта (из параметра `-a`) |


## Импорт в Firefly III

Официальная документация по импорту: https://docs.firefly-iii.org/how-to/firefly-iii/features/import/

Кратко:
1. Подними Firefly III importer (Helm-чарт или Docker)
2. Загрузи CSV через веб-интерфейс или API
3. Маппинг полей: `date` → Date, `amount` → Amount, `description` → Description, `source_name` → Source account
4. При первом импорте выгрузи JSON-конфиг маппинга полей
   (кнопка **"Download configuration"** в импортёре) — сохрани его рядом с парсерами, например как `configs/green_bank_config.json`. При следующих импортах просто загрузишь этот JSON, а не будешь мапить поля заново. Это экономит 5 минут рутины на каждый импорт.

**Важно:** Импортёр — это отдельный контейнер, который поднимается на время импорта и глушится после (`kubectl scale --replicas=0`). Не оставляй его висеть с write-токеном к API.

## Получение токена Firefly III

Для импорта через API нужен персональный токен:

1. Зайди в Firefly III → **Options** → **Profile**
2. Прокрути до **OAuth** → **Personal Access Tokens**
3. Создай новый токен, скопируй
4. Передай его в импортёр через переменную окружения `FIREFLY_III_ACCESS_TOKEN`

Токен храни в секретах (Kubernetes Secret, `.env` на локалке). Не коммить его в git.

## Честность парсеров

Около **10% выписок не парсятся** — форматы плавают. Это осознанное решение: скрипт **явно говорит** «не удалось извлечь данные», а не молча проглатывает половину.

Тихо потерянные транзакции хуже ручной доработки: бюджет, который врёт молча, не чинится никогда.


## Ограничения

- **~10% выписок не парсятся** и требуют ручной доработки
- **Форматы меняются без предупреждения** — следи за обновлениями
- **Парсеры не обрабатывают мультивалютность** (всё приводится к валюте карты)
- **Нет обработки дубликатов** — если импортируешь одну выписку дважды, получишь дубликаты
- **Скрипт упадет, если файл CSV уже есть** - в планах обработать это в исключениях.
